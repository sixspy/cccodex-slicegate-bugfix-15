# 日界锁定说明

> 本文件是「日切放行」系统策略锁定日界口径的**唯一权威说明**。系统内
> `backend/day_boundary.py` 的 `PLAN` 常量与本文件一致；运行时可经
> `GET /api/boundary/spec` 读取同一份口径。任何偏离本说明的动作一律拒绝，
> 并向 `boundary_audit` 表登记「日界口径偏差」。

## 一、钉死口径：甲方案

| 项 | 内容 |
|----|------|
| 选定口径 | **甲方案** |
| 口径含义 | 业务日切换（日切）在**同一事务内**作废昨日全部生效锁定；次日如需锁定，必须重新钉策略 |
| 选定日期 | 2026-11-17 |
| 当天是否可更换 | **不可更换**，代码中不存在切换口径的写路径 |
| 乙方案 | 显式结转 + 结转审计行——**未启用**；对 `POST /api/boundary/carryover/{lock_id}` 的任何调用都拒绝并登记偏差 |

选择甲方案的理由：彻底消灭「跨日静默沿用昨日锁定拒绝今日放行」的残留路径，
放行服务只承认当前业务日钉下的锁；规则单一，策略台与关日台不存在两套读数。

## 二、业务日与策略锁定生命周期

1. 当前业务日保存于 `biz_day_state` 单行表，**只允许日切事务更新**，禁止无审计改日界。
2. 策略锁定（`policy_locks`）由策略台经 `POST /api/slices/{sid}/lock` 钉下，
   锁定行的 `biz_date` 一律取当前业务日，调用方不得指定。
3. 锁定只有两种状态：`生效`、`作废`。作废原因只有三类：
   - 业务日切换作废（甲方案，日切同事务批量作废）
   - 放行服务跨日残留清理（兜底，见三）
   - 当日人工解锁（`POST /api/boundary/locks/{id}/void`，留审计）
4. 同一业务日同一切片只允许一笔生效锁定，重复钉策略被拒绝。

## 三、放行服务日界逻辑（修补落点）

放行（`POST /api/slices/{sid}/release`）在日界互斥区内按序执行：

1. 完整度不达标 → 拒绝并写「放行拒绝」流水与审计（原规则不变）。
2. 查询该切片全部生效锁定：
   - `biz_date ≠ 当前业务日` 的**跨日残留锁**：当场作废，写「跨日残留清理」审计，
     **绝不参与拦截**——未结转也不得拿昨锁拒绝今日放行。
   - `biz_date = 当前业务日` 的同日生效锁：拒绝放行，放行流水注明锁号与原因，
     写「放行拒绝」审计。
3. 无同日生效锁 → 放行成功，写放行流水（含残留清理笔数）、消费水位与「放行成功」审计。

## 四、日切与策略钉死互斥

- 日切（关日台 `POST /api/boundary/day-cut`）与策略钉死（策略台
  `POST /api/slices/{sid}/lock`）共用同一进程互斥量并以 `BEGIN IMMEDIATE`
  开事务，二者严格串行。
- 后手在超时（默认 3 秒）内拿不到锁时，动作**不执行**，系统登记
  「日界争用」审计并返回 409，提示后手动作已登记。
- 日切事务内容：推进业务日 → 作废全部生效锁定 → 写 `day_cuts` 流水 →
  写「日切」与「锁定作废」审计，全部同一事务，失败整体回滚。
- 业务日只能向前切换。回拨、原地不动、格式非法的请求一律拒绝并登记
  「日界口径偏差」；目标日缺省时按自然日 +1。

## 五、偏差登记（偏离说明即拒绝并登记）

`boundary_audit.event_type = '日界口径偏差'`，当前覆盖：

| 偏差尝试 | 系统行为 |
|----------|----------|
| 显式结转（乙方案入口） | 拒绝，登记偏差，锁不变 |
| 日切回拨/混子日（目标日 ≤ 当前业务日） | 拒绝，登记偏差，业务日不变 |
| 日切目标日格式非法 | 拒绝，登记偏差，业务日不变 |

偏差登记使用独立事务立即提交，不受被拒动作回滚影响。可经
`GET /api/boundary/audit` 查询全部审计。

## 六、五处读数一致

下列五处展示全部以 `biz_day_state.current_biz_date` 与
`policy_locks` 同库同事务数据为准，目录旁注与详情旁注由同一函数
`annotate()` 构造，不允许各自维护口径：

1. 策略台（`/api/boundary/state` + 前端「策略台」页）
2. 成功流水（`/api/releases`，含残留清理与锁定拦截备注）
3. 关日台（日切流水、偏差/争用计数，同 `/api/boundary/state`）
4. 详情旁注（`/api/slices/{id}/boundary`）
5. 目录旁注（`/api/slices` 每行 `boundary_note`）

只改前端提示而不写日界数据的改动不满足验收；任何日界状态变更都必须有
对应审计行。

## 七、约束备忘

- 不新开网页站点，不新增服务端口：全部能力挂在现有 FastAPI 应用与同一单页前端内。
- 会话登录照用原 Bearer Token 机制（admin / 123456），全部日界接口均需登录。
- 文件库仍是本机 `data/app.db`（SQLite），仅新增表，不引入外置存储。
